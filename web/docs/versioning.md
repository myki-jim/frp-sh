# 版本策略

## 当前阶段：开发中（0.x）

frp-sh 目前处于 **0.x 开发阶段**（语义化版本中 `major=0` 表示尚未稳定）：

- **功能与协议可能调整**：1.0 之前会持续加入新能力、修正设计，不承诺向后兼容
- **版本快速迭代**：0.x 阶段每周都有更新（当前 v0.3.x），建议跟随更新
- **1.0 才是正式版**：只有达到下面的门槛才会升为 1.0

## 1.0 的门槛

1. **功能定型**：房间 / 打洞 / 组网 / 更新治理等核心能力不再每周演进
2. **协议冻结**：线协议版本稳定，不再变动
3. **跨平台稳定**：Windows / macOS / Linux 的虚拟网卡、防火墙、权限在真实环境跑顺
4. **文档完备**：CLI 手册、FAQ、部署指南齐全

## 开发期的版本治理（1.0 前的安全网）

虽然 0.x 允许变化，但我们有机制保证"变而不乱"：

### 线协议版本（PROTOCOL_VERSION）

- 每个版本内置一个协议版本号（当前为 1）
- **向后兼容的新增**（如新增可选字段）不递增协议版本
- **破坏性变更**（改路由、改帧格式、改语义）必须递增，并发布说明
- 客户端连接信令服务器前校验协议版本：**不一致直接拒绝运行**（防止新旧混用出现无法解释的错误）
- 服务器通过 `GET /version` 暴露版本与协议号

### 更新检查

- 每次运行显示当前版本与协议版本（`frp-sh v0.3.7 (protocol v1)`）
- 启动时自动检查新版本（`frp.sh/latest-version.txt`，6 小时节流）
- 有新版本时询问 `[Y/n]`：
  - **平滑升级**（同主版本、次版本差 ≤ 1）→ 可跳过，下次启动再提示
  - **代差过大**（主版本不同，或次版本差 ≥ 2）→ 不可跳过，强烈建议立即更新
- 连接时显示服务器 / 房主版本：
  - 版本不同但协议兼容 → **黄色**提示
  - 协议冲突 → **红色**错误并拒绝
  - 连不上服务器 → **红色**错误

## 你的选择

| 需求 | 建议 |
|------|------|
| 尝鲜新功能 | 用最新版（`curl -fsSL https://frp.sh/install.sh \| sh` 一键更新） |
| 求稳部署（服务器） | 固定版本并留意更新提示；代差过大时务必升级 |

## 发布节奏

- `0.x`：功能开发与修复，随时发布（当前 v0.3.x：连接档案 / 一键接入 / 面板日志 / 打洞降级策略）
- `1.0.0`：首个正式版，此后遵循语义化版本（`1.x` 兼容，`2.0` 破坏性变更）
