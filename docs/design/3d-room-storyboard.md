# frp.sh 全 3D 官网分镜脚本 · v2

状态：已被用户否决并由“文字为主、3D 辅助展示”方案替代。保留本文仅供设计历史参考；当前实现见同目录 `website-visuals.md`。

## 核心叙事

**从一个人的桌面出发，邀请很多人进入同一个连接空间，最后回到自己的显示器，开始安装。**

房间代表共享的虚拟局域网空间，独立桌面代表不同成员的设备。多人共同加入同一房间，不再以两人配对作为故事终点。画面先展示 6–8 个成员，远景暗示更多参与者；这个数量只是构图选择，不宣称产品人数上限或无限容量。

全站是一个连续的 3D 场景。没有独立的平面功能卡片、横向营销板块或普通安装区。介绍、功能说明、语言选择和安装指令都寄托于场景中的显示器、门牌、桌面物件和空间运动。导航仍可直接跳到安装，不强迫用户看完整段故事。

默认英文，提供完整中文切换。所有演示为连接概念动画，不显示伪造的实时延迟、在线人数或测速结果。

## 美术与镜头

- 保留微缩房间、桌椅、窗户和生活细节。使用克制的暖白、深灰、鼠尾草绿和少量橙色信号线；通过精细几何、材质、光影与镜头形成科技感。
- 开场为能看清物件的微缩透视，结束为显示器正面近景，形成视觉闭环。
- 不同成员的桌面具有不同布局：笔记本、双屏、游戏控制器、书籍、不同桌灯，避免重复复制同一套模型。
- 连接速度通过短促、明确的响应表现：输入完成，信号发出，屏幕陆续响应。避免长时间等待动画，也不把动画时长当成真实连接耗时。
- 滚轮驱动故事进度；相机采用平滑轨道移动，转场以穿越窗框、门框、显示器边缘完成空间遮挡。文字在屏幕内按行揭示，遮罩来自真实场景构件。
- 没有默认声音。场景停留时只有低幅度的屏幕指示、桌灯变化或数据流动。

## 房间风格：不同的人住在这里

每个房间分别设计空间轮廓、窗型、家具、材质和个人物件。不能只替换墙色。首轮采用六个主要房间，远景成员沿用这套差异原则扩展。

| 房间            | 空间与材质                         | 人的痕迹                           | 夜间光源                                 |
| --------------- | ---------------------------------- | ---------------------------------- | ---------------------------------------- |
| 起点 · 木作书房 | 浅橡木桌、窄长窗、亚麻窗帘、低书架 | 笔记本、摊开的手册、陶瓷杯         | 暖色工作台灯，柔和屏幕反光               |
| 开发者阁楼      | 坡屋顶、天窗、深木梁、升降桌       | 双屏、机械键盘、拆开的设备         | 天窗冷色环境光、显示器、桌下低亮灯       |
| 城市工业工作室  | 高窗、清水混凝土、金属层架、长桌   | 线缆盘、工具盒、滚轮椅             | 轨道灯局部照明，窗外稀疏城市灯           |
| 游戏卧室        | 低窗、软地毯、矮床、紧凑电脑桌     | 耳机、控制器、沙发靠垫             | 遮光帘边缘漏光、屏幕光、克制的琥珀色背光 |
| 植物阳光房      | 转角落地窗、石材地面、藤编椅       | 大小植物、浇水壶、便签             | 落地灯照亮叶片，窗外轮廓柔和             |
| 复古电子工坊    | 磨旧木地板、玻璃砖窗、模块储物柜   | 小型 CRT、焊台、元件抽屉、旧说明书 | 绿调屏幕、局部工作灯，保留暗部           |

合并后保留各自地板、桌椅和灯光特征，通过共同通道连接。只收起阻挡相互交流的隔墙，窗框、屋梁或边柱可以保留，避免变成一间家具重复的大办公室。科技感来自设备响应和连接逻辑，房间本身有生活气息。

## 自然昼夜：同一个空间的两种光照

这是一套场景光照状态，不是网页背景颜色切换。首次访问参考系统明暗偏好，用户可在桌面上的昼夜旋钮选择“日间 / 跟随系统 / 夜间”；物件刻字随语言切换。手动选择会保存，不请求定位，也不推测用户真实日出时间。

- **白天**：光从具体的窗户方向进入，窗框投下阴影；天空漫反射照亮暗面，木材与织物保持自然颜色。屏幕发光较弱，桌灯可处于低亮度。
- **过渡**：约 2–3 秒经过暖色傍晚，太阳方向与强度、天空色和环境反射一起变化。室内灯具稍有先后地亮起，屏幕逐渐成为局部光源，阴影自然淡出。切换时不重置故事或移动镜头。
- **夜晚**：窗外呈深蓝灰色，环境仍保留物件轮廓；不同房间使用各自的台灯、落地灯、轨道灯与屏幕照明。没有全场统一蓝色染色，也不让霓虹灯淹没细节。
- **共同空间**：所有房间遵循同一个昼夜状态，差异来自窗向、遮挡、材质与灯具。日间用屏幕响应表示成员加入，夜间可以同时借助桌灯亮起，不能让白天动画失效。
- **阅读时刻**：关键门牌有自然补光，最终显示器根据模式调整亮度与反光。夜间不把整块屏幕变成刺眼白板。减少动态效果模式直接切换到最终光照状态。

昼夜切换在各幕都可使用：导览用的小型桌面控制器随镜头停靠到当前场景的桌沿或门边，拥有真实厚度、支架、投影和刻字；不固定贴在视口角落。旋钮、安装跳转与语言选择共用这个实体物件，避免遍布按钮。

## 文字就是场景的一部分

介绍文案不使用屏幕空间标题、字幕条、悬浮卡片或始终朝向相机的标签。每段文字都有明确的物理载体与合理用途：门牌上的房间号、显示器里的终端输出、说明书上的操作提示、线路检修牌上的路径说明、机箱上的开源铭牌。

- 字体随载体变化：门牌刻字、纸上印刷、终端等宽字；通过统一字重与排版保持整体一致，避免每个物件都变成广告牌。
- 文字遵循物体透视、遮挡与光照。印刷字随纸张受光，屏幕字从屏幕发光；不能穿墙显示或在转场时漂在物件前方。
- 镜头主动接近承载关键信息的物件，给读者停留空间。每个阅读镜头只传递一个意思，以短句为主，详细内容放进可打开的场景内手册。
- 不把八幕的所有宣传句机械地贴上墙。能通过成员加入、屏幕同步或线路选择解释的部分，优先用动作表达，文字只补充必要信息。
- 切换语言时替换同一载体上的内容，预留中英文长度差异；不增加第二套悬浮翻译层。
- 最后的安装指令仍位于真正的显示器画面内，允许选中与复制。实体按键承担系统选择与复制，反馈来自显示器中的终端状态行，而非网页通知气泡。

## 第一幕：这是你的桌面（0–10%）

**画面**：从木作书房的桌角移向电脑。日间窗帘轻动，光落在桌面；夜间台灯渐亮。窗外能看见其他风格的房间，电脑尚未响应。桌面保持真实尺度，不堆砌悬浮 UI。

**文字载体**：电脑屏幕。

- EN: “Your desk. A room for everyone.”
- 中文：“你的桌面，大家的房间。”

**动作**：滚动时椅子轻轻退开，屏幕亮起，显示一个简洁的终端。屏幕边缘露出“Scroll to connect / 滚动，开始连接”。

**交互**：桌沿的实体导览控制器提供刻字语言拨片、昼夜旋钮和安装快捷键。按下安装键，镜头直接进入最后一幕。

## 第二幕：创建房间，分享房间号（10–23%）

**画面**：镜头靠近显示器。终端中的创建动作完成，生成一个清晰可读的示例房间号。

**文字载体**：终端输出和桌边一张立起的小牌。

- EN: “One room code. Invite your people.”
- 中文：“一个房间号，邀请大家加入。”

**动作**：房间号从屏幕转换为门牌上的文字。橙色信号沿桌面、地板走向窗外，镜头跟随。随后分出多个方向，提前明确这是多人连接。

**说明**：创建命令、房间号格式和输出文案在实施时对照 CLI 校验；界面明确属于演示，房间号不作为真实邀请码使用。

## 第三幕：不止两个人（23–42%）

**画面**：镜头穿过窗框拉远，看到分散在不同位置、风格各异的多个房间。最初一个房间响应，接着第三、第四、第六个屏幕依次出现加入反馈；夜间桌灯也随之亮起。景深处还有其他成员桌面。

**文字载体**：每个房间的门牌显示同一个示例房间号；电脑显示加入状态。不会为每个房间堆叠大段文案。

- EN: “Different places. One room.”
- 中文：“身在各处，共处一室。”

**动作**：连接信号并行抵达多个桌面，各自出现明确的完成反馈。显示器里的成员列表从一个变成多个，且可以继续延伸。

**镜头**：横向穿行于不同工作空间，再升起呈现整体。横向运动发生在 3D 空间里，不将网页卡片横向搬动。

## 第四幕：同一个空间（42–56%）

**画面**：房间之间的外墙向下收起，独立地板逐渐拼成一块连续的共同空间。家具与个人桌面保留，中央形成开放的共享区域。

**文字载体**：共同空间入口的立体门牌。

- EN: “Together, on the same network.”
- 中文：“一起，连进同一个网络。”

**动作**：连接线由外部邀请路径转变为设备间的数据路径。成员屏幕同步出现状态变化，表达连接已经建立。

**表达边界**：空间合并是同一虚拟局域网的隐喻，不暗示所有流量必须经过房主电脑，也不暗示设备共享同一物理地点。

## 第五幕：一起做点什么（56–71%）

**画面**：镜头在共同空间内沿弧线经过两个活动区域，全程保留多人桌面作为背景。

**开发区域**：一个显示器中的本地页面发生变化，几个成员屏幕出现对应页面，光标分别移动。桌牌写 `Build together / 一起创造`。仅表达访问共享的本地服务，不演示未经产品支持的自动协同编辑。

**游戏区域**：镜头顺着桌面连接线转到另一组桌子。多个屏幕呈现同一局域网游戏的抽象场景，不使用第三方游戏素材。桌牌写 `Play together / 一起开玩`。

**动作**：在同一个房间内切换用途，家具无需全部变形。通过显示器内容、键盘响应、连接信号与镜头取景完成叙事。

## 第六幕：找到更直接的路（71–81%）

**画面**：镜头降低到地板高度。局部地板变为半透明，显露设备之间的连接路径。

**动作**：几条探测信号同时前进，可用的直接路径亮起；另一组受阻路径沿侧面的中继节点绕行，随后恢复连续传输。其他成员的连接仍然保留。

**文字载体**：线路旁嵌入地板的小型标识，仅在相关镜头内出现。

- EN: “Direct when possible. A relay when needed.”
- 中文：“能够直连，就直达。需要时，中继接力。”

**重点**：突出并行探测与直接路径选择。动画不演示保证零延迟、绝对最快或永不失败。

## 第七幕：让工具退到幕后（81–90%）

**画面**：镜头回到起点附近的桌面，经过电脑侧面的维护抽屉。共享房间仍然活跃。

**动作与信息载体**：

1. 一张安装授权卡进入抽屉，辅助服务指示灯留在机箱侧面。屏幕说明 `Authorize during installation. Connect from your usual account. / 安装时授权，日常使用普通账户连接。` 更新仍走安装器，不用“一次授权，永久无需授权”的绝对表述。
2. 主终端保持简洁，旁边一个小型辅助屏展示日志，明确日志与操作界面分开。
3. 机箱上的开源铭牌写 `Rust · Open source / Rust · 开源`，可点击打开仓库。体积数据如需保留，必须带比较口径；不让数字占据主镜头。

**转场**：镜头沿显示器支架上升，回到最初那台电脑。身后的多人成员仍在工作，故事由“大家”自然回到“你”。

## 第八幕：现在，轮到你了（90–100%）

**画面**：镜头停在显示器正前方。显示器占据主要画面，屏幕清晰、稳定，边缘仍能看到键盘和桌灯，背后的共同空间轻微虚化。

**屏幕布局**：

```text
frp.sh

Your next room starts here.
你的下一个房间，从这里开始。

> macOS / Linux

curl -fsSL https://frp.sh/install.sh | sh
Ready to copy.
```

实际显示所选语言，不同时堆叠两种语言。Windows 切换后显示：

```powershell
irm https://frp.sh/install.ps1 | iex
```

**交互**：显示器底座有带刻字的系统选择拨片与复制实体键。按下 Copy 即复制当前命令，按键产生短促按压反馈，屏幕原位显示 `Copied / 已复制`。复制不触发安装。平台切换可参考设备类型初选，始终允许手动更改。语言与昼夜控制器停靠在旁边，安装指南放在桌上的手册中，下载与源码入口使用机身铭牌。

**辅助文字**：屏幕底部简洁说明安装辅助服务、运行后配置自己的信令服务器，并链接安装指南。版本与下载地址由当前发布信息提供。

**停留**：此处滚动叙事结束，镜头停止漂移，命令不会自动消失或继续打字。用户可以选中文本、使用键盘切换平台和复制，也可以反向滚动重看故事。

## 场景内统一交互

- 语言切换贯穿所有场景，保留当前进度并记住选择。场景运动不因切换语言重播。
- 安装、返回起点、语言与昼夜控制通过场景中的实体导览控制器实现。它会在镜头停留点拥有可辨认的位置；键盘操作也可以直接到达这些功能。
- 门牌、纸张与铭牌使用物体表面的文字或刻字。最终可复制的屏幕内容可采用贴合显示器平面的语义文本层，严格同步透视、遮挡和边界；不使用独立网页卡片或悬浮按钮。实体控制保留对应的键盘与读屏操作，不能为了 3D 外观牺牲可用性。
- 手机重新安排镜头和物件距离，重点时刻放大单个屏幕；多人远景只短暂出现。最终显示器覆盖可用屏宽，命令区不会因模型透视而难以点击。
- 减少动态效果模式提供各幕静态机位与显式前进/后退入口；无法运行 WebGL 时显示可用的安装入口和文字说明。

## 实施与验收顺序

1. 灰模阶段：先做八幕镜头轨迹、多个房间布局、共同空间合并，以及最后的显示器复制交互。确认叙事连贯后再做材质细节。
2. 美术阶段：分别制作六种房间的空间与物件，完成日间、夜间及过渡光照，再加入屏幕内容、空间遮挡转场和连接信号。
3. 交互阶段：实体控制器、场景内双语文字、昼夜偏好、系统选择拨片、复制按键、直接跳安装、反向滚动、移动端镜头与降级。
4. 验收：能从窗型、布局和家具认出不同房间；观众能明确看懂“多人加入同一房间”；全部主要描述融入真实场景物件；最终显示器可读、可操作；没有虚构连接性能数字。测试日夜下的完整滚动、任意一幕切换昼夜、语言切换、快速跳转、手机布局及低动态模式。

实现时复用房间几何与材质，按距离减少细节，限制阴影和像素密度，离屏或隐藏时暂停绘制。性能预算以实际设备测量确认，不预先承诺固定帧率。
