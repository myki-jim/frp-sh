# 0.4.0 大版本实施计划

状态：核心改造已实现，开发分支验收中；实际结果与剩余发布门槛见 [验证记录](0.4.0-validation.md)。基线为 main 的 `e1037af9b4d5c37b0cf7613b88a0c08d70c00ff0`，已有安全修复和协议 v2。

## 目标与默认范围

1. 完全移除客户端和服务端 Web Panel，精简运行时与发布包。
2. 安装时统一请求管理员/root 授权；正常启动、建房、加入、重连、退出和重启机器后使用，不再请求授权。
3. 缩短首次连接与重连耗时，减少重复询问，明确失败原因。
4. 提供轻量、统一的终端交互；先支持简体中文和英文，默认跟随系统。
5. 运行日志独立于终端状态视图，具备轮转、脱敏、诊断和机器可读输出。

保留文档网站和安装下载站。删除的是内嵌管理面板。信令 REST、健康检查和 TCP/UDP/TURN 服务仍是网络功能的一部分。

本计划按当前发布平台覆盖 Windows、Linux 和 macOS；Linux 的 OpenWrt/procd 与其他非 systemd 环境需要单独验证，不以普通 Linux 编译通过代替支持承诺。

实现阶段采用 `codex/0.4.0-overhaul` 分支分批提交和推送，全部发布验收通过后再创建正式 `v0.4.0` 标签。若发生新的线上不兼容变更，再评估线协议是否需继续升级，不能仅依赖软件版本号。

## 核心架构：安装授权一次，日常 CLI 普通权限

安装器注册一个最小网络辅助服务。CLI、信令请求、密钥处理、P2P/TURN/TCP 会话与终端交互使用普通用户权限；辅助服务只承担虚拟网卡、受限路由和必要网络配置操作。

这里的“一次授权”指日常不再弹出 sudo/UAC。系统仍需保留一个有必要权限的受控服务来完成网络操作，不能在安装后让所有进程永久丢弃权限又随时修改系统路由。

| 平台 | 安装与运行方案 | 验收重点 |
| --- | --- | --- |
| Windows | 安装 Wintun 和 Windows Service；服务端程序及 DLL 存放于管理员保护的目录；CLI 通过本机命名管道调用 | 普通账户、重启后、并发会话均无 UAC；管道拒绝其他未授权账户、远程客户端与伪造服务 |
| Linux/systemd | 安装服务或 socket activation，限制能力集和设备访问；使用带对端身份校验的 Unix socket | 无 sudo 建房/加入；崩溃后清理路由；限制 CAP_NET_ADMIN 等能力到确有需要的服务 |
| macOS | 安装 launchd 系统辅助服务，通过受限本地 IPC 操作 utun 和路由 | 普通用户与重启后使用；签名/安装与系统版本兼容性实测 |
| OpenWrt/非 systemd Linux | 按目标平台提供 procd 等服务适配；不静默退回每次 sudo | 真机验证前明确标注尚未验收 |

服务边界必须先做原型验证：Unix 优先传递受限 TUN 文件描述符；Windows 对 Wintun 的服务端持有和有界数据通道做吞吐测试，避免为免提权引入严重复制开销。

IPC 请求使用版本化结构、对端身份认证、长度上限和超时；只允许安装时授权的用户或本地组操作自己创建的会话。禁止任意命令、任意可执行路径、任意文件写入和无限制路由配置。退出、IPC 断开、进程崩溃后按会话清理；网络配置修改需记录原值，只撤销本程序拥有的变更。

更新也纳入一次授权体验：辅助服务只安装固定来源、通过签名验证、目标匹配且版本策略允许的发布包，不能提供通用提权安装接口。分离下载与特权替换，支持原子替换与受控回滚。发布签名密钥的供应与保管是发布前依赖，私钥不得进入仓库。

## 实施顺序

### P0：基线与跨平台权限原型

- 保存二进制体积、安装包总大小、空闲内存/CPU、启动耗时和连接分阶段耗时。
- 当前 Windows Release 可执行文件为 9,640,960 字节；最终同时比较 CLI、辅助服务及安装包总成本。
- 记录典型 LAN、公网直连、UDP 受限/TURN、TCP 强制回退、网络切换和重启场景的 p50/p95、成功率、超时和重试次数。
- 实现最小服务生命周期和 IPC 原型，验证一次安装授权、普通用户创建与释放网卡，以及重启后恢复。
- 将单文件 `commands.rs` 中权限、会话协调、呈现输出拆出明确模块，为后续变更提供边界。

验收：拿到可重复的基线，且每个计划支持的平台都有可验证的权限实现路径；不能只删除提权检查。

### P1：彻底移除 Web Panel，精简依赖

- 删除 `src/panel/`、内嵌 HTML、WebSocket 推送、面板路由、本地 6793 监听、管理员面板令牌和相关启动逻辑。
- 删除面板专用环形日志、状态字段和流量上报；保留连接算法、诊断和终端确实使用的统计。
- 清理 `--panel-addr`、`--no-panel`、面板分享说明与对应测试；对旧参数给出明确迁移提示。
- 移除 Axum 的 WebSocket feature 和不再使用的传递依赖。服务端仍需要 HTTP 信令，不能直接误删全部 Axum 功能。
- 增加客户端精简构建配置，隔离 server/TURN-server 等服务端专用依赖；保留完整包兼容既有 `serve` 部署。
- 不引入浏览器内核或大型全屏 TUI 框架；以实际包体、内存和启动测量判断精简收益。

验收：二进制不包含面板资源；客户端无面板监听，服务端面板路由不存在；网络功能回归通过。提供同平台前后对比，新增辅助服务计入总开销，不只比较客户端单文件。

### P2：正式接入一次授权安装与服务

- 安装器一次性完成管理员授权、受保护安装目录、驱动/辅助服务、ACL、PATH 和必要的最小网络规则。
- 保留真实安装用户身份，用户 Profile、语言和日志写入其用户目录，避免写入 root/管理员的个人目录。
- 删除日常 LAN 命令中的 UAC 重启和 sudo 提示，改为本地服务调用。
- 服务缺失、版本不匹配、被停用时提供可操作的诊断，不循环弹出提权窗口。
- 覆盖升级、失败回滚、卸载和残留资源清理；卸载走受限维护接口。

验收：在干净机器安装时授权一次，此后普通用户首次连接、重复连接、重连、系统重启后的连接均不再次提权；越权 IPC、路径注入和篡改更新包必须被拒绝。

### P3：连接速度与流程优化

- 统一连接状态机：配置检查 → 信令/候选准备 → 路径竞争 → 身份认证 → 连接完成 → 重连/退出。
- 版本检查和更新提示移出连接关键路径；版本结果按服务器短期缓存。
- 在依赖允许时并发准备 DNS、局域网候选、公网探测和必要的 relay 预连接，复用 HTTP 客户端与已有探测结果。
- 设置候选优先级和有限的回退启动延迟；UDP 不通时无需等待所有串行超时结束才尝试中继。
- 采用首个完成认证且真正可用的路径；取消并回收其他尝试，避免幽灵房间、重复 HOST 和 TURN 分配泄漏。
- 连接建立后不盲目替换承载中的字节流；本版先优化建链，在线无损迁移只有具备明确迁移协议和回归测试才加入。
- 重连采用有上限、有抖动的退避；认证失败和配置错误直接报告，避免无限重试。
- Profile 复用、配置预检与默认值消除每次重复输入，失败信息注明发生阶段及下一步操作。

验收：固定环境至少各 30 次采样，与 P0 对比。目标为冷启动/重连 p95 降低至少 30%；LAN 已就绪场景争取 1 秒内可用。指标是受控场景目标，不承诺任意公网秒连；连接成功率不能因缩短超时下降。丢包、慢读取、认证失败与大数据传输测试必须继续通过。

### P4：终端界面、多语言、独立日志

终端采用紧凑状态卡：房间、设备、当前阶段、连接方式、延迟、流量和快捷操作；成功后原地更新状态，避免持续刷屏。取消每条命令重复的大幅 ASCII 横幅。

交互模式只显示用户需要采取行动的信息与连接状态。支持窄终端、ASCII 回退、`NO_COLOR`、`--no-color`、`--plain` 和非 TTY 环境；退出时恢复光标和颜色。

先支持 `zh-CN` / `en`，提供 `--lang auto|zh-CN|en` 和配置项。优先级：命令行 → 用户配置 → FRPSH_LANG → 系统区域 → 英文。翻译覆盖安装、向导、help、参数错误、状态、业务错误和更新提示；错误码及 JSON 字段保持稳定。必须在 Clap help/错误生成之前解析语言设置，避免仅翻译运行后的界面。

独立日志继续使用现有 `log` 接口，后端改为有界异步写入，避免网络任务持有文件写锁。采用按进程/会话隔离的日志文件、大小或日期轮转、总容量限制和文件权限约束；记录阶段、耗时、错误码和会话标识。删除仅供面板使用的缓冲区。

提供 `logs path`、`logs tail --follow`、按级别/会话筛选，以及默认脱敏的诊断导出。所有输出链路过滤 password、key、owner token、Authorization 与 URL 中的凭据。日志满、磁盘满、写入失败不能阻塞隧道；明确丢弃策略并记录丢弃计数。

日志保持稳定英文事件/字段，终端按语言渲染。`--json` 输出结构化事件时 stdout 不混入横幅、颜色或日志；错误保持稳定退出码。`-v` 提高文件日志详细度，不破坏交互终端。

验收：两种语言无缺项和占位参数错配；非 TTY 输出可被脚本解析；终端不中断、不混日志；多进程日志轮转安全；注入测试凭据不会出现在日志或诊断包中。

### P5：整体验收、推送与正式发布

- 原有安全回归、端到端直连/TURN/TCP 与多人组网全部通过。
- Windows/Linux/macOS 安装、普通用户运行、重启、升级、卸载完成对应平台验收；网络性能和总安装大小附对比表。
- 运行 rustfmt、Clippy、全部测试、精简与完整构建、安装脚本验证和文档构建。
- 更新 CLI、配置、安装、服务管理和 0.3.x 迁移文档，清除面板旧入口。
- 扫描本次提交和发布包的凭据，核对发布清单、校验和、签名与跨平台资产名称。
- 逐阶段普通推送开发分支；最终合入 main，创建 `v0.4.0` 标签并核验 Release 与安装下载。除再次发现必须清理的泄露内容外，无需重复重写历史。

## 依赖与发布门槛

签名发布体系、Windows 服务/Wintun 实测、macOS 辅助服务安装与签名、Linux 不同服务管理器是主要跨平台依赖。开发环境无法实际运行的平台要明确记录“未验收”，不能用 CI 交叉编译冒充测试完成。

瘦身、免重复提权与性能需要共同验收：增加辅助服务后仍应报告总安装体积和总常驻开销；不能通过让完整网络客户端常驻 root 来省略权限边界设计。
