# frp-sh 0.5.0

This release uses signaling protocol v3 and network-helper protocol v2. Upgrade the server and reinstall clients before creating new rooms.

- Game defaults to multiplayer virtual LAN and interoperates with LAN rooms. Game servers accept explicit TCP/UDP ports; there is no implicit 25565.
- Dev supports up to 16 host-published services, concurrent TCP/WebSocket/SSH streams and isolated UDP source flows. Service rooms currently use encrypted TCP relay; virtual LAN retains direct P2P networking.
- Terminal app home includes game, server and development flows. Profiles: run `frp-sh profile`, or open the app and press `2`. Services show actual bound addresses; I opens invitations and G opens logs.
- New v2 invitation links carry revocable room credentials, not the server administrator password. `dev revoke` closes established relays and invalidates invitations. `dev add` and `dev remove` update the active host's catalog.
- Loopback-only service targets/listeners, bounded streams/queues, allocation quotas, private packet destination checks and source-route checks prevent unintended exit proxy behavior. Public listeners require authentication.
- Relay pairing releases its waiting slot immediately after pairing; expired pending handshakes no longer hold slots for ten minutes.

Validation: eight concurrent members with 64 TCP connections and 16 UDP flows; live local CLI create/join/rejoin/add/remove/revoke; encrypted relay cancellation; existing networking/security regressions. Native helper checks run in platform CI.

Limits: no universal game discovery, no automatic physical LAN sharing, no arbitrary Internet publishing. Service publishing is controlled by the room host. UDP over TCP relay has ordered-delivery latency. A deliberately published application-level proxy still requires operator access policies; these controls are not a claim that abuse is impossible.
