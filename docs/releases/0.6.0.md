# frp-sh 0.6.0

0.6.0 adds durable device membership and a restricted public HTTP ingress while keeping signaling protocol v3 and helper protocol v2 compatible with 0.5.x.

## Added

- Durable spaces stored in SQLite, Ed25519 device identity, stable virtual addresses, revocable members, and encrypted member relay that does not depend on the owner staying online.
- Single-use invitations valid for 15 minutes by default, plus `space join --stdin` to avoid placing invitation tokens in shell history.
- Native background supervisor installation for Windows SCM, Linux systemd, and macOS LaunchDaemon. Installation requires administrator access; normal start, stop, and status operations do not.
- Custom-domain commands: `domain bind`, `verify`, `status`, `publish`, and `unbind`.
- DNS TXT ownership verification, exact Host routing, loopback-only HTTP targets, bounded requests and responses, one-time publisher tokens, and Caddy allowlisted On-Demand TLS.
- The frp.sh community custom-domain gateway uses `edge.test.frp.sh` and HTTPS port `18443`. Public port `443` is reserved for ACME TLS-ALPN certificate validation.

## Operational notes

- Self-hosted durable spaces require an HTTPS/WSS reverse proxy, a private SQLite path, and `--spaces-origin`.
- Self-hosted domain ingress requires `--domains-db`, `--domains-origin`, `--ingress-addr`, `--ingress-cname`, and `--ingress-https-port`. Use the split TLS policies in `ops/caddy/Caddyfile.example`; the Caddy `ask` endpoint is mandatory.
- The first domain ingress release forwards ordinary HTTP requests only. It does not expose arbitrary TCP/UDP, CONNECT, or public WebSocket upgrades.
- Existing LAN, Game, Dev, profiles, and legacy room invitations keep their prior behavior.
